### 🔗 X-y 配對邏輯

由於 X 的日期數量（56個）多於 y（33個）,兩者並非一一對應,配對規則如下：

> 針對每一個 **y 的日期**,在 X 資料夾中尋找 **小於等於該 y 日期的最大日期** 所對應的資料夾,作為該筆樣本的輸入影像。

例如：y 日期為 `20230130`,若 X 資料夾中有 `20230115`、`20230125`、`20230201`,則會選擇 `20230125`（最接近且不超過 y 日期）作為配對的 X。

配對時同步記錄 **X-y 天數差**,作為後續「時間差輔助特徵」的輸入來源（詳見「⏱ 時間差輔助特徵」章節）。

## 🔀 訓練、驗證、測試切分

### 時間獨立（Time-independent split）

| 用途 | 資料範圍 |
|---|---|
| 訓練 / 驗證 | 2023年，共 37 個日期，依 **7:3** 切分 |
| 測試 | 2026年，共 12 個日期 |

### 空間獨立（Spatial-independent split）

- 資料範圍：2023年與2026年，共 **49 個日期**、**11 個區塊**
  - 區塊清單：`N1`、`N2`、`EN`、`E1`、`E2`、`E3`、`W1`、`W2`、`W3`、`W4`、`W5`
- 切分比例：訓練 : 驗證 : 測試 = **7 : 2 : 2**

> ⚠️ **已知限制**：切分是先對完整大圖依「時間」或「空間」進行切分,之後才進行 patch 切割。因此：
> - **時間獨立切分**時,空間上可能存在洩漏（同一區塊同時出現在不同時間切分的樣本中）
> - **空間獨立切分**時,時間上可能存在洩漏（同一時間點同時出現在不同區塊切分的樣本中）
>
> 此為資料特性所致的取捨,目前先接受此限制,不另外處理。

## ✂️ 資料切割（Patch 切割）

| 用途 | 影像大小 | 移動步輻 |
|---|:---:|:---:|
| 訓練 | 256 × 256 | 128（= patch_size × 50%） |
| 驗證 / 測試 | 256 × 256 | 256（= patch_size） |

> 📌 因資料量過大，改以 **`.json`** 檔案儲存每個 patch 的切割資訊，內容包含：
> - 日期
> - 區塊名
> - 切割的 x、y 位置
> - 灌水比例
> - SCL（=3, 8, 9）比例

> 🧩 **SCL 的另一項用途**：除了用於 patch 篩選外,SCL（尤其是 **水體類別 SCL=6**,經驗證與灌水事件有高度關聯）會另外經過 **one-hot encoding**,作為模型的**輔助輸入特徵 channel**,與 Green/Red/NIR/SWIR 一併輸入模型,而非僅用於資料篩選。

## ⚙️ 前處理流程

適用波段：**Green、Red、NIR、SWIR**

1. **Step 1**：去除非農地範圍數值
   - 判斷依據為 **對應 y 標籤 == 999**（非農地範圍),以此建立 mask 後套用到 X,**不使用 X 本身的 999 來判斷**（因 X 的999在農地範圍內為合理反射率,僅在非農地範圍才代表遮罩值）
2. **Step 2**：剩餘數值取 **1st ~ 99th 百分位數** 進行上下界裁切（clip）
   - 統計量（百分位數上下界）僅使用 **訓練集** 資料計算,再套用到驗證 / 測試集,避免資料洩漏
3. **Step 3**：除以 **10000** 後，再計算 **mean / std**（供標準化使用）
   - 同 Step 2,mean / std 僅使用 **訓練集** 計算

## 🧠 模型設定

| 項目 | 設定內容 |
|---|---|
| 模型架構 | **UNet**，encoder = `resnet34` |
| 損失函數（criterion） | 結合 **BCE** 與 **Dice** 的複合 Loss |
| 優化器（optimizer） | **AdamW** |

### ⏱ 時間差輔助特徵

- X 與 y 的實際觀測日期不一定完全相同(依「X-y 配對邏輯」取最近日期),因此額外加入一個**與影像同尺寸的常數平面（constant plane）**,數值為該筆樣本的 **X-y 天數差**,作為輔助輸入 channel
- **正規化**：天數差除以資料視窗上限（`nday20` → 除以20）,使數值落在約 0~1 範圍,與其他波段的數值尺度對齊,避免此 channel 在梯度更新中比例失衡
- 此 channel 與 SCL 皆屬於「輔助 metadata channel」,分別反映**資料新鮮度**與**資料品質**

### 🔧 輸入通道調整（Encoder 修改）

- `resnet34` 預訓練權重的第一層卷積為 **3 通道**（RGB）設計,而輸入資料為 **Green、Red、NIR、SWIR 共4個波段,再加上 SCL one-hot 特徵、時間差輔助特徵**,總通道數 > 3
- 修改方式：**將 RGB 三通道權重取平均,複製到所有新增通道（第4通道起,包含波段通道、SCL one-hot 通道、時間差通道）**,其餘沿用預訓練權重

### 🎯 Loss 計算時的標籤排除規則

- **y = 999（非農地）**：排除,不計入 loss
- **y = 0.5（當期作有灌水）**：排除,不計入 loss

### ⚖️ 類別不平衡處理

灌水像素佔比極低（實測全域盛行率約 2.24%）,採取以下兩項措施：

1. **BCE 加入 `pos_weight`**：提高正樣本（有灌水）在 loss 中的權重
2. **訓練時對高灌水比例的 patch 做 oversampling**：利用資料切割階段 `.json` 中已記錄的「灌水比例」欄位,提高含灌水像素比例較高的 patch 被抽樣到的機率

## 🔬 待評估的優化方向

以下為參考同類研究（Sentinel-2 灌溉/水體判斷、不平衡類別分割任務）整理出的延伸優化方向,尚未定案,列出供後續討論：

### 特徵工程
- 加入 **NDVI**、**NDWI / LSWI** 等衍生指數作為額外輸入 channel（可用現有4波段直接計算,成本低）
  - NDVI = (NIR−Red)/(NIR+Red)：反映植被生長狀態
  - NDWI/LSWI = (NIR−SWIR)/(NIR+SWIR)：對地表/植被含水量敏感,是判斷灌溉的關鍵指數之一

### 時序資訊
- 目前 X-y 配對僅取「最近一次」X,模型只看單一時間點快照
- 建議評估是否加入**前一次(或前兩次)X**,讓模型能學習變化趨勢(例如 NDWI 的時間差分),而非只有絕對值

### Loss 函數
- 除了目前的 BCE + Dice,可額外嘗試：
  - **Tversky Loss**：可分別調整 False Positive / False Negative 的懲罰權重,比單純調整 `pos_weight` 更精細
  - **Focal Loss**：加大對難分類樣本的權重

### 後處理
- 形態學操作（如 opening/closing）去除孤立小區域雜訊
- 正式產出全圖預測時,改用**有重疊的滑動窗口 + 平均融合（overlap-average stitching）**,避免無重疊patch拼接時的邊界不連續瑕疵

### 評估指標
- 因類別極度不平衡（盛行率約2.24%）,accuracy 參考價值低
- 建議以 **F1、IoU、MCC（Matthews Correlation Coefficient）、PR-AUC** 作為主要評估指標

### 資料品質
- 確認 train / val / test 各切分之間的雲量（SCL品質）分布是否相近,避免驗證結果過於樂觀
- 「含弱相關」的灌水網格樣本,可考慮依信心程度給予較低的 loss 權重,而非與高信心標籤一視同仁

### 預訓練權重
- ImageNet（自然影像 RGB）與衛星多光譜影像的 domain gap較大,建議後續做消融實驗：比較「使用 ImageNet 預訓練權重」vs「從頭訓練（random init）」的效果差異,不預設預訓練一定有幫助
